# PubMed abstract reconstruction correction

This additional development patch is separate from the frozen intent experiment. It is not deployed; production containers and search settings are unchanged.

The active PubMed `_get_previews` calls `_get_article_abstracts`. That method seeded its output with the first `AbstractText.text`, then looped over all sections and appended the first section again. It also used `.text`, which omits nested element content/tails. Primary abstract selection used all descendant `AbstractText` nodes, potentially mixing `OtherAbstract` translations with the primary record.

The candidate reconstructs the primary `MedlineCitation/Article/Abstract` sections once, in order, using the existing `xml_text` helper and section labels. Nested text/tails remain; super/subscript roles receive explicit markup labels rather than being flattened ambiguously. It does not interpret scientific meaning, change query scope, filter sources or infer a missing result. Other abstracts remain distinct rather than being merged silently; a record with no primary abstract remains unavailable in this path.

Before editing, the previous module and a real NCBI efetch XML response for eight papers were frozen in `/data1/maxw/ldr-evaluation/pubmed-abstract-integrity-20261110/`. Raw XML SHA256: `c4c8c76ebd811a70705218f7793a371cd5eab8883eb61767727a3f2955ac8b1e`. `scripts/check_pubmed_abstract_integrity.py` executes the exact adapter method against the same frozen response. The former output matches the primary XML reconstruction 0/8 times because of duplication. The final candidate matches exactly 7/8, and 8/8 after whitespace normalization: the shared markup helper changes Unicode thin spaces around one P-value into ordinary spaces. An earlier plain itertext candidate matched exactly 8/8 but flattened nested super/subscript roles; it was replaced by the existing role-preserving helper. Both final arms return the same eight identifiers. Results: `evaluation/pubmed-abstract-integrity-20261110.json`. Neither whitespace equivalence nor retained markup roles is a semantic truth score.

These eight records contain no nested abstract markup, so they validate removal of real duplication, not observed recovery of nested scientific text. Three separate synthetic parser contracts cover nested text/tails, scientific comparisons, section order and separate translations. Synthetic cases establish parser behavior only. The comparison does not measure search recall, report usefulness, citation entailment or overall hallucination reduction; token/context allocation and report-quality effects remain unmeasured.

The evaluation-preparation regex error found in the intent experiment is a different failure. Production Europe PMC already uses `research_verify.retrieval.html_text`, an HTMLParser-based helper; checking it on the saved API records retained the subgroup results. The corrected intent packs use a parser too and are regenerated under unchanged model/candidate settings. The old lossy packs and drafts remain marked invalid for a complete-abstract comparison.
