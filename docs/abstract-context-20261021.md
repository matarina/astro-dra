# 摘要优先的材料组织、500来源池与全文路径改进（2026-10-21）

## 实现

- 常规候选来源默认及硬上限200→500，Compose与示例env同步。fetch原有独立登记路径保留，故总数仍可能超过常规池限制。
- handler文档元数据保留原始abstract。formatter不再80000//N等分原文，选中的来源完整呈现已取得的摘要；其他长正文仍取原文片段。单次来源材料目标20万字符（含书目头，不含问题/草稿/检查反馈），摘要不足时允许正常生成有依据的整理，不要求每篇全文。
- 来源材料不超过20万字符时直接提供，不新增材料选择调用。超出时分成约5万字符的批次，使用同一模型按问题选择原来源编号；最终在预算内交错接纳各批优先条目，实际材料仍为原文，不使用生成摘要替代。只接受本批内合法JSON编号，异常按有界原候选降级并记录，不猜测编号。未选材料保留在研究池，不自动删除报告或更改编号。
- 新增URL分类overlay，共享academic_url_ids按真实host/path识别Europe PMC MED/PMC及新PMC域名；MED页面进入PubMedDownloader文本API路径，不再直接当普通网页。PDF备用路径也支持MED映射。既有自身PMC映射与XML身份检查保留。
- 身份核对后的XML按标题/摘要/正文段落及章节提取，排除作者、机构、参考文献，保留内嵌文字。抓取上限1万→50万字符；将获取/保存的原文与模型读取片段分开，模型视图从整份已获取文本检索约1.8万字符的原文窗口。focus与full模式都保全原文，长文仍有界；不代表每次模型读完50万字符或所有付费/非开放文章可取。
- trace脚本支持候选镜像/500容量隔离整链测试，材料选择调用单独标phase=source_context_selection。
