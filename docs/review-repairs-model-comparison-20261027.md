## 测试设计及产物范围

私有根目录`/data/ningh/nh/ldr-experiments/review-repairs-models-20261027/`。用户可读原始报告和链接集中在[reports/model-comparison-20261027.md](../reports/model-comparison-20261027.md)。

1. `fresh-flash`：原问题，全新搜索与Agent流程，实际默认langgraph-agent、max_iterations=50；1397.264秒、104来源、50参考、无research_error。自动PubMed全文关、原生事实检查开、保存前QC关。官方Flash只在隔离测试内覆盖，网页不切换。第一版三项编排修复候选SHA49018ed…；不代表最后所有修复后再跑整轮。
2. `compare-v4`/`compare-flash`：冻结test001的214来源，包括当时已经取得的争议原文；保持同一实际writer_request。先对固定旧成文核对，再跑14个聚焦案例，最后同材料重写与核对。固定成文12组首轮核对提示哈希全部相同。V4和Flash完整对照分别48、57次推理调用。文档获取冻结，不假装这是两次相同检索轨迹。
3. `nonthinking-*`：同一14例，双方显式thinking disabled。`final-*`：加入肾脏摘要/明确原文/正确对照及训练验证表格，18例；适配及表格修复候选。`applicability-*`：相同18例，加入未声称属性协议。两类通用合成对照明确标记，其余取真实来源；不是18篇都做全篇人工核查。
4. `confirmation-*`：最终确认提示下4例（错误疾病/正确疾病、合成样本单位/正确推荐参数），仍双模型、显式关闭thinking；不是另一轮全新研究。实际生产review_answer与确认入口执行，保留所有误判。
5. 身份桥另用原test001来源池及真实元数据服务／冻结原始回复验收，不将联网成功当语义检查通过。

所有默认完整对照使用第一版编排候选，真实实跑后才暴露适配和格式问题。后续聚焦结果及回归用于验证这些新增修复；不把前面五份完整报告标作最终全部补丁的结果。各目录manifest记录当时产品模块SHA、请求模型名、温度0.7、max_tokens30000、材料及提示哈希。

“获准修订多”不是总体准确率，“未决少”也不是正确性。Flash有正确原句被误报缺证的情况；原子分项有时把原句未声称的属性写成not_reported。协议修复后部分对照恢复正常，但最新参数对照仍误报，原句未被修改。缺证一般保留正文并私有记录未决，不会因标记而自动删除／改成相反结论。

同材料Flash重写避免旧稿几处问题，可能也改变案例覆盖，不能当作对旧报告逐条修复率。新检索Flash纠正两处MISO训练/验证，另修一处APA来源限定，但这两处表格行被原候选改成普通段落，触发最终结构保护。新报告仍有“12只雄鼠肾”歧义、期刊条件未落实及额外平台内容；原始文件保持原样。

## 能归因到哪一层

**工程层已证实**：无编号web不调用、段落引用切断、版本未决丢失有稳定回归；原子短引适配及表格破坏由实跑直接暴露。确认提示把“原名错了”与“换成另一个实验”混淆。以上不能靠换模型替代。

**证据层已证实**：肾脏摘要足以阻止12肾写成12动物，但不提供6动物关系。补入原文明示数量与技术重复的片段后，Flash能纠正；原文见[Nature Communications](https://www.nature.com/articles/s41467-025-62599-9)／[PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC12354736/)。不过V4在同样补证下仍漏判，说明证据充足也不保证正确。IF条件没有指标输入，不能归因于模型不知道某篇摘要。

**模型／服务语义层已证实存在漏判**：输入及来源身份未变时，仍错判平台章节归属、单位及正例；同一模型不同推理模式或重复单次结果也变化。V4经常识别冲突但给省略号而非原文，属于证据输出不合约；程序拒绝不可定位证据是预期保护。不能为提升“修订数”放宽为随便引用。

**不能确定底层权重能力排名**：调用分别通过原V4网关、官方Flash，返回别名与请求相符，但无法由别名核实具体权重和网关内部处理。Flash默认长推理明显增加耗时：首组同提示V4约16.9秒、Flash约91.9秒；Flash回复含14205个reasoning token，V4网关未提供同样明细。另做双方显式disabled控制；未据此改生产推理配置。少量样例、温度0.7及不同服务不能支持稳定准确率排名。

## 未宣称解决的范围

- 同文章在原文证据、元数据都缺标识桥时，不能用标题相似度擅自合并；服务没有映射也不能宣称去重成功。
- 无显式关联的两个相似预印本不能自动判同一版本。正式版替换仍须实际文本支持、独立确认，可能保留两版及未决原因。
- IF>10逐篇条件、原始研究/综述/预印本的覆盖验收仍不完整。新报告承认不知道指标比虚构指标好，但仍不等于完成用户筛选条件。
- 章节隐含平台归属、缩略术语、技术体系分类、未声称属性误报仍是语义难点。需要通用研究—输入数据—分析用途的上下文约束与跨主题验收，不能继续添加疾病/数字/平台专用关键词规则。
- 本轮不自动打开PubMed全量全文、不恢复保存前审计、不加发布门槛、不换网页默认模型。用户仍能得到报告；私有未决不等同通过。

## 身份桥的真实验收与限制

官方[PMC ID Converter API](https://pmc.ncbi.nlm.nih.gov/tools/id-converter-api/)提供精确编号转换。宿主机探测旧路径和当前路径都遇HTTP403，Europe PMC的CORE真实回复又只有PMC身份；因此最初的仅Europe PMC实现未消除原86/163重复。

补上官方转换后，在与5002相同容器网络、实际安全请求及代理配置下，**正式API成功返回PMC13646825↔PMID42847244↔DOI10.1093/nar/gkag937**。回放真实test001全部来源与正文，STAT3D书目由原[39]/[40]两条变为一条，original_indices保留[86,163]。两个来源各自文本和原编号保留，没有按标题匹配、改DOI或手工指定这篇映射。真实EPMC/PMC HTTP事件、映射结果保存在私有identity-bridge-live.json。这是身份去重修复的实际验收，不是模型能力提升；宿主机403也不能直接当生产容器失败。

联网失败或服务没有映射时仍可能保留重复，记录unavailable/no_alias，不能强行合并；独立12秒/4请求、失败缓存，不增加无限重试。补齐获取的是元数据，不开启PubMed自动全文。应用仍由既有publication负责书目去重和编号。

诊断脚本最初一次读旧构建镜像得到ImportError，两次隔离环境没有可写LDR_DATA_DIR导致PermissionError，已单独保留并修正测试环境；这些失败不计产品功能验收。之后真实服务回复获取成功，不能把早期测试环境错误当搜索故障。
