## 修改与对照范围

仅试改`research_verify/generation.py`中的共用GROUNDING_INSTRUCTIONS，不加入小鼠/肾脏/特定数字/论文规则，不改检索、材料选择、原生检查或最终稿修订流程。两版内容：

- 第一版：转述数字时保留计数对象、单位、限定范围；不明确时保留原文范围，不推断另一种数量。增加三行。
- 第二版：翻译/概括数字时明确写出被计数对象，并使用输出语言中无歧义的表达；保留单位和限定范围，不将数量转给相关对象或推断未报告数量。增加四行。

使用原生deepseek/deepseek-flash。研究端捕获实际安装Agent代码组装的系统提示，直接提供最新任务中保存的两篇真实来源：原80/PMID39478210（病例/肿瘤切片/匹配测量样本），原265/PMID40813851（肾脏样本）。固定中文问题，比较旧提示、第一版、第二版各一次。该测试不执行工具，不是完整Agent研究过程。

写作端复用2ac66cfe任务完整215425字符writer_request，保留原问题、103条来源、歧义草稿和原生反馈；三组仅替换共用提示，分别真实调用一次。没有补入Methods的6只动物证据，也没有重新运行原生检查。已校验研究端/写作端第二版相对baseline只改变该段共用提示；输入输出保留在私有目录。

## 实际结果

| 版本 | 研究端摘要生成 | 完整写作请求回放 |
|---|---|---|
| 原提示 | “12只雄性小鼠肾脏” | “12只雄性小鼠肾脏” |
| 第一版 | 同样写“12只雄性小鼠肾脏”，表格又写“雄性小鼠肾脏（12只）” | “12只雄鼠肾” |
| 第二版 | “12只雄性小鼠肾脏”；还明确写“雄性小鼠模型（12只）”，并称为摘要未建立的纵向研究 | “12只雄性小鼠肾” |

因此不能声称已修复。第一版、第二版保留歧义；第二版研究输出另有明确的动物总数断言。另一篇论文的131切片/78病例/35切片口径在对照中基本保留，但写作输入的旧原生反馈已指出该问题，不能把它作为新提示的效果证明。没有对所有输出语义逐项验收，也没有统计准确率结论。

两版最终回归343 passed（最后一次1.90秒），隔离镜像的模拟流程检查通过；这些仅说明代码和流程可运行，不代表语义修复通过。共8次真实请求尝试，其中6次生成成功，另2次最初人工构造工具历史的请求被接口以OpenAIInvalidRequestError拒绝，未计为语义对照结果；之后研究端改用同一真实来源直接输入，没有修改产品接口来迁就测试。

研究成功调用约14.7–24.9秒，完整writer约137.0–152.2秒。相同模型单次生成存在波动，每组一次不能证明两版提示的总体优劣；本例结果已经不足以支持部署。试验没有新增完整研究任务或修改用户DB/历史报告。
