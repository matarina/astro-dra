## 1. 首先发生的是搜索偏题

正确的 Visium/Nature 检索词返回 Stephen Curry、篮球统计页；其他空间平台查询返回会计作业、Instagram 和公寓信息。最早 39 个被纳入的 SearXNG 来源均为这类无关网页。

绕过 LDR 直接查询同一个 SearXNG 已重现，查询回显正确且无后端报错；通过当前网络路径直接查询 Bing 也重现查询词正确、结果明显无关。因此异常先于生成，不是最后参考文献重排产生。尚未定位 Bing 服务、访问路径或响应处理中的精确根因，不能直接归咎代理或声称某一方篡改。

独立探测保存在实验目录的上一级：`spatial-searxng-probe-20261019.json` 和 `spatial-bing-probe-20261019.json`。这只说明本次访问状态；此前搜索引擎审计中的成功不能保证每次查询相关。

安装默认 `search.skip_relevance_filter=True`，通用网页搜索没有这道模型相关性筛选。即使搜索 HTTP 200、返回了十条，也不能说明这十条可作论文证据。

## 2. PubMed 查询被放宽，候选资格也没有落实

首批优化后的查询包括：

```text
(Visium[Title/Abstract] OR "spatial transcriptomics"[Title/Abstract])
AND (method*[Title/Abstract] OR analysis[Title/Abstract])
```

Xenium 和 Stereo-seq 也出现了类似“目标平台 OR 全领域名”的查询。OR 使没有目标平台的研究和综述也可进入结果；日期、文章类型、JIF 没有成为这批检索的可靠约束。

最初保留的 41 个 PubMed 来源含 6 个 Review、2 个 Preprint 的 publication_types。预印本 URL 拦截并不等价于排除 PubMed 中被标为 Preprint 的记录。候选中 journal_quality=pending 也不能算 JIF 已核实。这是候选池问题，不能据此声称这些记录全被写成合格研究。

本次还记录到 NCBI E-utilities HTTP 429 共 52 次、Nature 404 共 18 次，以及 Europe PMC 403、TLS/代理错误等。它们影响召回和材料获得；单次报错不能证明某个论文不存在或不能获取。

## 3. 约 39 秒即占满来源池，之后多数搜索无法贡献新证据

安装版 `SearchResultsCollector.add_results()` 的默认容量为 80，按先来顺序收集；没有将早期偏题来源替换为后续更相关论文。38.560 秒达到容量，其中网页 39、PubMed 41。

147 次收集器调用中，139 次输入非空、返回给工具的列表却为空；原因混合了去重、容量及其他过滤，不能把 139 次全部说成上限丢弃。达到容量后仍有新的、未保留的相关标题进入，例如 “High-definition spatial transcriptomics visualizes cellular and molecular architecture underlying perineural invasion in localized prostate cancer”（PMID 42681671）。这些候选的最终纳入资格仍需另核实。

重复记录会合并到已有来源，但不会作为当前搜索结果返回。于是 Agent 看到“No results”可能只是该批没有新增，而非搜索引擎没搜到。它继续改词、抓搜索结果页，消耗工具轮次。

`find_or_add_result()` 的 fetch 注册路径没有同一容量检查，所以最终来源数仍涨到 135。这不表示常规检索上限已解除。

## 4. 材料在抓取、摘要解析和写作格式化时损失

### 抓到的内容没有完整交给写作模型

55 个 fetch 来源中，54 个在最终来源字典中没有保留 full_content，snippet 不超过 203 字符；另 1 个后来通过同一 URL 的 PubMed 结果合并获得摘要字段。这不能说明工具从未读过更长材料。

例如原来源 98，PMID 36385528：页面工具实际取得 10029 字符（含截断提示），注册后的材料只有约 200 字符摘要。写作模型拿到的是后者。38 个 fetch 来源的标题明确是 PubMed 搜索结果页，不能作为单篇论文 Methods 的依据。

抓取工具本身还有 10000 字符上限。即便页面来自 PMC，截取开头也可能主要是作者、单位、摘要和正文开头，未覆盖 Methods 或补充方法。因此 get_full_text=False 不等于所有 fetch 都只有摘要；拿到带正文的页面也不等于已经读全论文。

### PubMed XML 的内嵌标签确实截掉了一个真实摘要

原来源 99 为 [Tumour evolution and microenvironment interactions in 2D and 3D space](https://pubmed.ncbi.nlm.nih.gov/39478210/)，Nature，2024，DOI 10.1038/s41586-024-08087-4。

事后独立请求 EFetch 得到 HTTP 200。完整 AbstractText 的 itertext 包含 Visium、131 张肿瘤切片、跨组学整合、空间亚克隆、三维重建及邻域分析等内容；当前 `.text` 只取到了上标引用之前的一句开头，后面的正文丢失。安装版还重复拼接第一段，最终来源字典中的 abstract 只有同一句开头重复两遍。这是数据解析错误，不能称作“原论文摘要本来不够详细”。

### 论文元数据存在于来源字典，却未完整进入模型可见格式

旧 `_format_sources()` 基本只输出 `[编号] page_content`，没有统一附标题、URL、期刊、年份、DOI、证据范围。来源 99 的字典有题目和 DOI，但本次实际最终写作提示词里找不到这两个字符串。

最终 full_content 合计 194186 字符，其中 Study Metadata 后的机构、资助等文本约 80858 字符。输入很长，关键摘要却可能已经被截断；“提示词有 21 万字符”不等于“模型拿到了丰富的方法证据”。

## 5. 默认轮数耗尽后的兜底，只读前 20 个来源

这是本次拒答的直接触发点。

研究进度到 Step 50 后，正常 Agent 仍要求继续抓取；随后进入 `_synthesize_from_collector()`。该函数固定遍历 `results[:20]`，没有使用全池中后到的论文或有效抓取结果。这 20 个来源全是早期偏题网页。

按安装版函数和已保存来源精确重建的提示词长 5260 字符；其 SHA-256 与 1131.030 秒那次真实模型输入哈希完全相同：

```text
18eb15bb332cfbcb877dd40816e1aa616de857ff5dddc55134c3addf57a4404f
```

因此不是仅从输出猜测模型看了什么。兜底据此生成了 475 字符的英文拒答，声称来源全是篮球、作业、狩猎、公寓等。

然后 StandardCitationHandler 仍拿到全部 135 个来源，构造了 211986 字符的最终综合输入，并把这段拒答放在 Previous Knowledge。最终模型沿用了拒答方向，称审查了“40 份资料”，忽略了后部空间研究材料，也没有完成所需表格。

传输了 135 个来源，不代表模型有效利用了 135 个。可以确认输入和输出不一致；目前没有服务端上下文截断证据，不能把“只总结前 40 个”直接解释为模型服务裁掉了后文。错误初稿的影响、早期垃圾来源和长输入都是需要分开回放验证的因素。

## 6. 本次确实复现了范围引用的重排漏洞

单个引用的映射为：原 1→展示 1，原 40→展示 2，原 11→展示 3，原 12→展示 4；这些可识别的单个编号保持了原来源身份。

但模型还输出了 `[1-10]`、`[16-19]`、`[13-15]`、`[20-29]`、`[30-39]`。当前 claims 与 citation_display 正则只识别单号、逗号列表，范围没有展开，也没有重排。原文若按范围理解，引用了原来源 1–40；最终书目却只有 4 条，范围仍为旧值。

具体后果：原来指篮球网页的 `[1-10]` 留在正文，展示编号 2 已变成肿瘤微生物组综述。读者按最终编号读范围，会得到错误对应，还会遇到书目不存在的编号。最小离线复现：`cited_indices('篮球资料 [1-10]。') == []`，但逗号列表 `[1, 2, 3]` 能得到 1、2、3。

这是排版/引用解析层的真实问题，应修复统一解析及映射；不能据此认定所有单号引用都有错，也不能认为修好它会让科研内容自动正确。

## 7. 辅助引用核查不能替代任务完成度判断

本次辅助审计提取的 4 条带可识别引用陈述全为 unverifiable，仍按当前“辅助、不自动删改”策略保存正文。completed 仅表示审计结束。

只带范围引用的句子未被当作带引用陈述处理；“整个材料池没有合格研究”的全称断言，也不能靠一条文献片段的局部支撑核查完成。审计还出现把引用编号误解成页码的模型误判，不能直接据此计算领域准确率。

## 调整优先级与此前补丁的关系

1. 先恢复相关论文的稳定召回：排查当前 Bing 访问结果异常；PubMed 查询保留平台等约束，避免 OR 泛化；将综述、预印本和 JIF 未核实候选与可用于实际分析提取的研究区分。未授权扩大自动引擎池，本轮没有添加后端。
2. 改来源选择与兜底：避免先到的无关网页占满名额；明确区分“没有命中”“重复已见”“容量未纳入”；兜底按全池相关性和平台覆盖选材料，不能机械截前 20 个。单纯加大 Agent 轮数会继续放大无效搜索。
3. 保全证据：修复 PubMed XML itertext、第一段重复、fetch 文本只保留短摘要，以及写作输入丢失论文元数据；针对 Methods/补充材料定位提取，不把网页开头截取视为完整方法。
4. 再优化研究与写作：先形成逐论文、逐分析的证据条目，再综合共用模块；旧草稿只作结构参考，不能压过新证据。输入按论文与问题压缩，减少机构等无关元数据；解释性建议与论文实际分析分开。
5. 修复引用范围：让生成、审计、书目、展示共用能解析范围的编号逻辑，先展开旧范围，再按新映射渲染；保持正文与书目一致。

此前 2026-10-19 的未上线改动已涉及摘要 XML、fetch 保留文本、来源材料格式、重复来源复用及证据提示，方向有依据；但没有修复本次暴露的上游偏题、先到先得容量、兜底前 20 个选择和范围引用。因此不能声称只部署此前补丁就能完成本题，也没有本题补丁前后准确率提升的实测。

本轮新增的是通用追踪脚本和诊断文档，没有修改应用实现、构建镜像或部署。脚本静态语法检查通过，单号/范围引用解析差异离线复现；完整运行的真实保存/装配及两种导出成功。原始失败报告保留，未人工改写成成功报告；没有恢复强制删改或发布门槛。
