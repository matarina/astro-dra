# 5002 登录持久性排查（2026-10-30）

> 文档定位：仅诊断；登录持久性未修复。本页记录当时过程；当前状态见[状态总览](current-status.md)，有效后续见[待办](roadmap.md)。

用户仅使用5002，每次勾选30天，闲置失效时长不固定。本轮只读生产检查，在独立容器及独立测试卷复现；没有更改生产认证逻辑、Cookie配置或重启生产。

实测勾选项提交remember=true，浏览器收到HttpOnly/SameSite=Lax、有效期720小时的会话Cookie；保存Cookie后新浏览器上下文可访问首页。当前UI保留原生字段，未发现勾选项失效。

原生SessionManager在进程内维护SID，普通空闲期限2小时、remember为30天；数据库会话密码存储固定24小时且读取不续期。模拟remember空闲3小时后API200；25小时仍有数据库连接时API200，但凭据已过期。显式模拟数据库连接回收后，3小时可恢复/API200，25小时无法恢复/API401。因此不能将24小时凭据到期直接等同于固定24小时强制注销。

真实浏览器保存Cookie后仅重启隔离容器：签名密钥保持不变，但首页重定向登录。原生SID与凭据存储均只在内存，持久签名密钥和30天Cookie不能恢复丢失的服务端状态。

生产当前为sidebar-5002-20261030，启动03:37UTC、RestartCount0、无OOM；后续仍有两次登录，故不能用最近部署解释所有随机掉登录。实际仅一个Web主进程，Python子进程是multiprocessing resource tracker，未发现多Web worker轮转证据。正常日志未包含认证失败细因，尚未复现用户所述较短、不固定的闲置失效，不将上述两项局限冒充该现象的唯一根因。

测试材料在私有ldr-experiments/auth-5002-20261030目录，包含Cookie/测试账号关联材料，不提交。安全摘要见findings.json，浏览器重启验证见restart-proof.json。隔离时间测试仅调整内存时间戳，不等待真实25小时；连接回收为显式模拟，并非证明生产自动回收发生。

后续应在认证入口记录不含Cookie/SID/密码的失效原因以定位真实401，再分别处理remember会话与凭据期限衔接、可撤销持久会话及加密数据库恢复。不能跳过服务端会话校验、把密码明文持久化或靠无限心跳规避问题。部署认证补丁需要重启，会使现有内存登录失效；本轮未做此操作。
