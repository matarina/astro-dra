# 子任务第二版：有界检索、独立交付和过程保全

日期：2026-11-04。本页记录当日实现与测试，当时未部署；后续按用户指令于2026-11-05 08:38:14部署并重启5002，见[部署与回退](subtask-handoff-v2-deploy-5002-20261105.md)。未提交合入main，核查部分另行处理。[当日测试结果](subtask-handoff-v2-20261104.json)。

## 解决什么

[上一轮真实任务](subtask-handoff-live-4926df11-20261104.md)的3个子任务都在达到图步数限制后退出，正常返回后的总结、原文交付和消息记录均未执行。共享来源池虽有材料，主任务却没有收到各子任务完成的作业，随后写作仍发生方向反转。这个失败不等于检索没有结果，也没有证据认定为上下文超限。

现在把子任务明确分成“找资料”和“交作业”两段。找资料用完预算后关闭搜索循环，用已经取得的材料单独交付；交付模型出错时仍返回实际材料和未完整交付状态。总结负责阅读导航，具体事实另附可追溯的原文。本轮不把原文存在当作总结语义已核实。

## 实现

1. **留出交付预算。** 原最大模型决策数为8时，至多7轮用于检索和阅读，最后一轮工具结果返回后停止搜索。需要收尾时最多单独调用模型一次，使用新的材料上下文、不绑定检索工具。若已自然结束并提交有效作业，则直接使用，避免重复调用。原参数仍可覆盖；实际预算写入trace，不单纯调高迭代上限。引擎内部相关性判断和网络重试不属于这7轮Agent决策。
2. **每个子任务保留自己的材料。** `SubtaskCollector`仍共享原收集器的编号与去重，但用ContextVar和锁记录当前子任务实际新增或访问的来源、完整可用文本及更新。收尾只使用这些材料，不从其他并发子任务的来源池随意取文。实际LangChain工具线程传播已验证。
3. **异常也能交付已有成果。** 图迭代异常或普通搜索错误后保留最后消息、来源和退出原因，尝试独立交付。模型超时、坏格式或无法选出原文时，返回按子专题词项相关度排列的真实材料与partial状态；这是通用选材顺序，不判断科学结论。没有文本材料时不再凭空调用模型写总结。用户取消继续向外传播，不启动交付调用。
4. **总结改为研究导航。** 明确要求方向、值得阅读的论文/用途、报告结构、材料缺口四栏；允许空栏，避免为填格式编造内容。详细机制与数字留在原文栏。兼容旧字符串返回，但仍标为未核实梳理，不宣称格式能够杜绝语义错误。模型不规范返回时保留其生成文字及真实材料，不自动删改报告。
5. **原文由程序提供。** 沿用第一版逐字定位、短摘要完整保留、长文上下文、来源元数据与SHA；每个子任务原文预算24000字符、单片段8000字符。供独立交付模型阅读的材料也是有预算的真实材料，并明确省略/不完整状态；完整记录仍在来源池和私有trace，不能假称全部读过。
6. **逐步留痕。** 新增每轮AI/Tool增量消息、实际轮数/剩余预算、文本长度、模型提供的token统计、来源更新、搜索结束原因和交付请求/回复。即便最终invoke不正常返回也能分析此前过程。沿用原私有记录器的脱敏、权限和容量限制；模型未提供token时不编造。

实现：`local_deep_research/research_verify/subtask_research.py`、`subtask_handoff.py`及`langgraph_agent_strategy.py`接入。既有安装器自动复制新增research_verify模块，manifest目标无需增加。默认模型、三源、来源预算、保存前QC及自动全文开关未调整；`evidence_flow.py`、共享`generation.py`、原`synthesis_trace.py`哈希与本轮基线相同。

## 边界与接续

这版验证了预算结束后的交付和原文保全，未做跨题目准确率基准；模型仍可能误选材料、写错研究导航或在主写作中误读原文。本次真实检索只覆盖模型选择的内容，不保证搜齐目标论文；原文相同也不意味着结论正确。核查漏判尚未修改，现有事实检查仍不能当作可靠的语义通过证明。图预算不强行中断已在执行的HTTP请求，保留既有超时与外层1800秒限制，未整体解决取消后的残留工作和长尾延迟。
