# API-record identity provenance — 2026-11-11, undeployed

The candidate replaces URL/boolean-based bibliographic confirmation with metadata bound to a returned API record. Registry absence, incomplete responses and conflicting identifiers remain explicit states. It does not establish scientific truth, peer review, citation entailment or improved report quality.

## Changes and scope

PubMed ESummary, Europe PMC search and the existing Crossref/PubMed validator retain a small receipt derived from the returned record: provider/endpoint, record ID, identifiers, normalized bibliographic title, supplied publication types and a SHA256 of the raw record. No extra lookup is added. `record_identity.py` binds the receipt to the source's explicit identifiers and title; there is no title-only merge. Opaque Europe PMC collection IDs retain their namespaces and case, without requiring a biomedical collection code or DOI. Known PMID/PMCID/PPR namespaces receive syntax checks.

A PubMed-shaped URL, a DOI string, a bare legacy `verified=True/False`, or a generic warning no longer proves record existence or nonexistence. Explicit local-ID/URL disagreement and returned-ID disagreement remain conflicts. Missing record/title or an extra unconfirmed alias remains candidate. A matching primary record is not negated by a secondary lookup that simply did not complete. This is conservative metadata binding, not a guarantee every supplied field is correct.

Identity, document type, publication state, peer review and scientific support remain separate. Bound API publication types take precedence over stale local type labels; `Journal Article` remains `journal_article`, without implying original research or peer review. Publication states describe `indexed_record`, `registered_record` or an explicit preprint record. Web/vendor origin alone does not imply an unpublished work, and preprint origin alone does not establish publication or review state. Confirmed preprints can have confirmed identity with unknown review status. No source or draft claim is removed.

Crossref 404 now means `not_found_in_registry`, with `verified=None`, rather than a globally invalid DOI. Crossref documents that its API exposes deposited Crossref metadata and that `/works/{doi}` returns a Crossref record; it is not a universal DOI validity service. See the [official REST API scope](https://www.crossref.org/documentation/retrieve-metadata/rest-api/). A preserved direct HTTP counterexample returned Crossref 404 and DataCite 200 for the same DOI, [10.5281/zenodo.4663312](https://doi.org/10.5281/zenodo.4663312); the frozen [DataCite endpoint](https://api.datacite.org/dois/10.5281/zenodo.4663312) response contains that exact ID. These requests corroborate registration only. DataCite was used for this engineering check, without adding a production search or validation backend. Browser-tool API opens failed; direct HTTP statuses and original response bytes are retained with hashes.

Malformed/empty/error responses and a returned DOI/UID different from the requested identifier remain unknown. A positive validator result means the requested identifier was returned by that provider; title/year comparison and scientific meaning are separate. The visible badge says the identifier record was found, rather than presenting a generic verified claim. PMID extraction accepts an explicit positive integer, a complete PMID label or canonical PubMed URL, including historical short IDs. It does not mine study counts from prose or interpret a PMCID as a PMID. DOI extraction does not inspect object representations for an embedded string.

The receipt reaches evidence cards, native document metadata and publication metadata. The material header labels bibliographic identity rather than calling the grouping “publication status.” `GROUNDING_INSTRUCTIONS` is byte-identical and no new model instructions are introduced. Bibliography grouping uses identity status, so confirmed preprints are not mislabeled as unconfirmed leads. The unconfirmed group is a paragraph within the Sources section, preserving the existing parser's bibliography role. Save-time QC stays disabled and publication status remains unverified.

Receipts document processing by trusted adapters. They are **not cryptographic source authentication**: an external caller can forge a dictionary, and the raw-record hash does not bind acquired body text to that record. Same-ID title comparison uses existing cosmetic normalization; version/role/metadata differences can conservatively produce conflict or unknown and need resolution. Legacy unattested records remain available as candidates. Historical reports are not migrated. More cautious states may affect synthesis or model context; that effect is not measured here.

Of the passes, 117 are the focused generation/source/provenance/validator/PMID checks; eight are in the broader legacy citation-audit file.
