## 实际新增记录

容器目录 `/data/research_traces/<research_id>/` 位于现有持久数据卷内，每次Agent收尾、引用综合和publication各有独立trace_id子目录，避免章节和并发任务互相覆盖。每个目录的events.jsonl含阶段、UTC时间、相对耗时、状态、文件字节数和摘要哈希；正文为编号的.json.gz文件。

| 阶段 | 记录内容 |
|---|---|
| agent_finalization | 最终研究草稿及问题、Agent保留的消息与工具调用/返回内容、当时收集器来源。包含无来源/后续引用综合失败时的草稿。 |
| input_sources | 引用处理器收到的来源字段白名单，保留摘要、snippet、content/body、full_content、fetched_content、身份及书目信息等；不保存设置快照。 |
| source_selection | 超预算时每批真实选择提示、允许ID、请求数量、模型回复、解析后的选中ID或失败兜底。 |
| writer_sources | 实际格式化后提供给检查和写作的材料全文及来源ID列表。与候选池分开记录，不把“取到的全文”自动等同于“模型看到的文本”。 |
| native_check | 实际检查提示、处理器收到的模型content、最终使用的反馈文本和哈希。 |
| writer | 实际写作提示、收到的模型content、归一化后返回文本和哈希；流式中断会标partial及错误类型，沿用既有不重复请求的行为。 |
| publication | 重编号前正文、原始来源，重编号后正文、原编号到展示编号/论文身份的映射、warnings和audit_status。可用正文哈希关联writer输出。 |

“收到的模型content”位于SDK/ProcessingLLMWrapper之后，不是HTTP传输原始响应，也不保存HTTP鉴权头、连接对象或私有设置。没有逐token保存网络包或每次搜索的原始HTTP/XML；Agent消息保存的是进入其状态的工具结果，收集器另保留选定来源字段。若更早的引擎解析有问题，仍需对照原始接口。

## 原生检查这轮改了什么

仍是原生StandardCitationHandler的一次写前检查，没有恢复已关闭的逐引用QC。

- 加入用户问题，检查草稿正文时同时考虑小节标题、表格分类。
- 通用地要求核对“技术/输入数据/分析任务”与被引研究的对应关系，避免一篇论文的多个实验被混为同一数据分析。
- 核对数字在数什么、单位和独立观测/重复测量；不补推材料没有建立的样本层级。
- 区分真实冲突与不同人群、实验、模态的差异；缺少摘要细节不等于论文没有该内容。
- 请求简短可执行反馈，包含草稿位置、原编号、可用原文和需澄清点；不要求新JSON格式，不增解析重试。
- 最终写作的通用证据说明补充同样的分析输入关联，并明确标题/表格也要保持关联。

现有顺序仍为“Agent草稿→选材→原生检查→最终writer→编号/保存”。检查反馈仍通过原有提示交给writer。写作之后新增的错误仍不能被这次预检查看到；本轮先使错误进入点和反馈采纳情况可观察，不声称彻底解决。后续是否调整检查位置/如何反馈，应在新任务证据基础上决定，未自动重开逐引用审计或做写后删改。

## 开关、权限和容量

全局默认 `LDR_RESEARCH_TRACE_ENABLED=false`；5002私有环境显式设true。Compose将目录固定在/data/research_traces，其他服务不启用。任务ID不能作为任意路径；目录0700、文件0600。来源字段白名单、已配置凭据和常见密钥/鉴权字符串脱敏；普通日志仅打印 `[SYNTHESIS_TRACE]` 的研究ID、trace_id、阶段、状态和耗时，不打印材料或提示正文。脱敏之外保留实际输入输出文本。

每个记录单元（不是整个任务或整个磁盘）默认64MiB未压缩累计上限，单文件最多16MiB且不超过该单元上限一半；超限在事件中标omitted_size_limit，不截断后伪称完整。采用gzip压缩；历史记录暂不自动删除，后续需按保留需求清理。写入、初始化或磁盘故障只产生短诊断，不能阻断研究。记录completed只表示该记录范围的函数返回，不是事实核验通过；应另看partial/errors及实际任务保存状态。
