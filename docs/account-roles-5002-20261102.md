## 使用方式

注册页可选普通用户或申请管理员。普通用户注册后即可使用；申请管理员的账号在root批准前也可以按普通用户使用。管理员审批状态会显示在页面顶部。现有5个账号按用户确认保留为管理员，新增独立root账号。

| 角色 | 页面和权限 |
| --- | --- |
| 普通用户／待审批账号 | 新建研究、对话研究、研究记录；文献库、资料合集、下载管理、研究笔记、资料搜索、Zotero；研究资讯、订阅管理 |
| 管理员 | 保留原有统计、评测、设置及研究高级配置 |
| root | 管理员全部功能，另有“账号与审批”页面，可批准／拒绝管理员申请或撤回管理员权限 |

普通用户首页保留研究问题、报告形式和开始研究，移除访问范围、模型、端点／密钥、引擎、迭代及策略控件。桌面与手机导航均按角色展示。个人主题、修改密码、资料操作和个人Zotero配置仍可使用；订阅创建也提供简化表单。

root登录后打开 `/admin/accounts` 审批；其他管理员不能审批。批准或撤回后，账号的下一次请求立即使用当前权限，不要求重新登录。已启动任务已经捕获的参数不会被中途改写。

本机root初始凭据在私有目录 `ldr-experiments/accounts-5002-20261102/root-5002-initial.json`（0600）；不提交。没有网页注册root的入口或固定默认密码，可通过页面顶部修改密码。

## 后端实现

新增 `local_deep_research/astro_accounts/`，与引用核验模块独立。`store.py`在原`ldr_auth.db`增加角色、审批审计与迁移标记表，保留原生用户模型及每人独立加密数据库，未增加密码字段。一次性迁移仅保留当时已有账号的管理员权限，之后缺少角色记录的账号按普通用户处理，不会因重启自动提升。

注册角色记录与原生用户INSERT使用同一事务。普通用户和申请管理员初始角色均为user；只有root审批能改变角色。SQLite外键级联清理保证加密数据库创建失败时删除角色记录，不留下阻塞后续注册的孤立行。root名称保留，公开注册不能选择root角色；已有同名账号时迁移拒绝自动接管。

`web.py`检查服务端最新角色。普通用户直接访问设置、统计、评测、模型发现、嵌入配置、程序化研究API及全局调度管理会被拒绝；只放行主题、帮助折叠、个人资料行为和Zotero等必要的个人设置。研究接口拒绝普通用户提供模型／引擎／策略／访问范围等覆盖，以及嵌入metadata的配置。审批沿用原生登录校验和CSRF保护，审批和撤权留数据库审计。

`policy.py`在共用SettingsManager读取和快照层对普通用户使用部署默认值与LDR环境覆盖，包括llm、search、embeddings、rag、policy、report、chat、benchmark、rate_limiting。管理员个人配置不作为全体用户配置来源；统一服务配置由部署环境和默认配置维护。为SQLCipher引擎附加账号身份，不依赖其没有文件名的SQLAlchemy URL。权限每次重新读取，后台／对话也能应用。普通用户的旧个人模型配置不会重新进入快照。

原生订阅存在绕过Flask中间件的内部调用，所以研究入口也处理普通用户参数；后台订阅的显式模型／引擎覆盖会移除。新旧两套订阅接口均限制普通用户提交服务配置。没有更改研究提示词、检索相关性、引用处理或默认模型；本轮亦没有处理此前登录持久性问题。

## 构建与root初始化

`deployment/Dockerfile.accounts`在当前sidebar镜像上安装账号模块和界面。完整`deployment/Dockerfile`也已接入账号安装器，完整构建已验证。`install_accounts.py`在固定原生文件的明确位置安装7个小钩子，先检查位置唯一及Python语法，再写入；不匹配的新上游版本会中止构建。UI-only安装器仍只接受模板和静态资源。

新部署初次需要由服务器运营者创建root。先启动应用以完成角色表迁移，再在服务器终端执行（替换Compose项目名／env路径）：

```bash
read -r -s -p '设置 root 初始密码: ' task_root_password
printf '%s' "$task_root_password" | docker compose --env-file .env.test-5002 -p astro-dra-test-5002 exec -T --user ldruser local-deep-research /install/.venv/bin/python -m astro_accounts.cli
unset task_root_password
```

CLI通过标准输入读取密码，使用原生密码校验和加密数据库创建。已有root时只报告exists，不重置密码。当前5002已创建，无需重复执行。
