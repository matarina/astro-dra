## 1. 已确认的业务决策

1. 默认使用最新已发布年度的 Journal Impact Factor（JIF）。任务开始时选择可核实的最新发布版本，固定指标年度、发布版本及数据来源；任务运行中不自动切换版本。若不能确认最新版本或缺少该期刊数据，则为待核验，不用旧值、CiteScore 或其他指标代替。论文发表年份与 JIF 指标年度分别保存。
2. 关键词只统计文献正文，排除参考文献。摘要和搜索片段只能用于候选检索，不能作为全文核验通过的依据。默认排除独立摘要、参考文献及页面导航等非正文；方法、结果、讨论等正文段落与正文图表说明纳入。补充材料单独记录，默认不纳入。
3. 四个明确关键词至少命中三个不同关键词；重复出现不增加覆盖数。用户关键词不被模型静默替换，同义词、缩写和跨语种映射需在任务规则中显式记录。
4. 严格任务只允许全部必需检查通过的文献作为正式证据。失败、未知、核验超时和关闭核验均不能等价为通过。
5. 文献不足时返回已核验结果及不足原因，不放宽筛选条件，不凑数。
6. “2026 年”限定为 2026 年；“2026 年以来”表示下限。默认按正式出版版本首次在线发表日期筛选，另存卷期出版日期。支持 > 与 >= 等比较符，不把 IF>10 改成 IF>=10。
7. 默认接收正式发表、可确认出版身份的期刊文献；预印本、撤稿文献不进入正式证据集，其他类型需任务规则显式允许。元数据冲突进入待核验。

## 2. 当前代码基线与已发现缺口

实际部署补丁在 local_deep_research/；local-deep-research/ 是旁置上游源码。
旧 Dockerfile 使用上游 latest 镜像并 COPY 补丁；新增根目录 compose.yaml 与 deployment/Dockerfile 固定基础镜像 digest 并按清单安装补丁。仅修改旁置上游源码不会自动影响部署。

- research_verify/ 已有 DOI、条件、关键词、引用检查模块，可复用 HTTP 和基础模型。
- langgraph_agent_strategy.py::_finalize 已接入检查，但处理的是已生成的 final_answer，且候选仍交给引用处理器；打标不等于从报告证据中排除。
- 单一年份被解析为下限；年份/语种/IF 未知不构成硬性拒绝；语种存在按检索引擎推断英文的路径。
- IF 读取没有携带指标年度与来源证据，不能直接宣称满足最新 JIF。
- keyword_cov.py 按长度推断全文，存在摘要误认；cli_check.py 把 PubMed 摘要放入 full_content。
- citation_qc.py 只处理有引用的句子、截取开头片段并合并判断，多篇引用没有逐篇关系；模型给出的 supporting_fragment 未校验原文存在性。
- current_knowledge、formatted_findings、findings.content 等报告出口并不完全共用最终核查正文，详细报告及累计来源还需专门审计。
- 旧文档的完成勾选和既往测试记录不作为新严格要求的验收证明；当前版本需重新建立基线。

## 3. 系统边界与数据契约

不重写检索内核。检索可以使用宽泛网页和摘要发现候选，正式报告生成只能读取合格文献的证据。

流水线：
任务规则 -> 候选发现 -> 身份与出版状态核验 -> 元信息筛选 -> 全文获取与解析 -> 正文关键词核验 -> 合格证据库 -> 报告生成 -> 结论核查/修订 -> 统一发布与审计。

建议新增或扩展的数据对象：

| 对象 | 最少保存内容 |
|---|---|
| TaskPolicy | policy_version、任务规则快照、年份及日期口径、比较符、语种、JIF 版本、原始关键词及显式别名、正文范围、数量与资源预算 |
| CanonicalPaper | 稳定 paper_id、DOI/PMID、标题、作者、期刊、ISSN、正式版本、出版日期、语种及各字段来源 |
| CheckResult | pass/fail/unknown/not_applicable、reason_code、证据引用、核验时间、核验器版本 |
| JournalMetric | ISSN、JIF 数值、metric_year、release_version、数据来源、获取时间、原始记录标识 |
| FullTextArtifact | paper_id、网址/文件来源、格式、提取器版本、内容哈希、身份校验、完整性状态、正文与排除区段 |
| KeywordEvidence | 原始词、匹配形式、命中片段、页码或章节及字符偏移、distinct_hits、阈值 |
| ClaimEvidence | claim_id、原子结论、paper_id、原文短引、定位信息、支持范围、逐篇判定、判断理由 |
| ResearchAudit | task_id、规则快照、候选与筛选计数、拒绝/待核验原因、文献与结论证据关系、最终发布状态 |

准入为显式聚合函数：所有必需项 pass 才 admitted；存在 fail 为 rejected；否则 pending。
not_applicable 只能由任务规则确定，不能由异常处理产生。
文献和结论使用稳定 ID；显示引用编号单独映射，筛选后重新编号，禁止沿用候选编号造成错引。
核验异常记录 unknown，任务可返回部分结果；不得回退发布未经核查的旧 agent 文本。
不在验证模块关闭时显示“严格核验通过”。

### M2：全文与正文关键词

依赖 M0，最终联调依赖 M1 的稳定文献身份。
- [ ] 实现全文获取适配：出版商可访问 HTML/XML、PMC 开放全文、用户提供的 PDF。
- [ ] 正文与文献身份关联，识别摘要、缺页、扫描失败、截断或错误页面；长度不是全文判据。
- [ ] XML/HTML 使用结构划分正文与参考文献；PDF 记录页码、文本位置及章节边界。边界无法可靠识别时 pending。
- [ ] 清理导航与参考文献，保留原始解析结果和排除范围；统一 Unicode、大小写、断词与连字符处理。
- [ ] 短词采用边界匹配，处理明确短语/别名、关键词去重；用户少于三个关键词时不得使用固定“三词”阈值，保存合理且显式的任务阈值。
- [ ] 修复 CLI 摘要误标；摘要可用于候选预筛，严格全文检查不能通过。
交付：逐篇关键词命中证据、正文覆盖状态和可复核定位。

### M3：结论与逐篇引用证据

依赖 M1+M2 的合格证据库。
- [ ] 报告生成只读取已准入文献及证据片段；过滤前的 agent 草稿不能绕过准入作为 previous_knowledge 使用。
- [ ] 拆分事实性原子结论，覆盖没有引用的结论及表格；区分叙述事实、推断和建议。
- [ ] 每个结论与每篇被引文献分别建立关系，不用合并片段掩盖其中某篇不支持。
- [ ] 在正文中检索相关证据，避免仅使用开头 1500 字；每个模型返回引文校验原文存在性与定位。
- [ ] 核查对象、数值、单位、方向、研究类型及限制；相关性不能自动写成因果性。
- [ ] 允许多个来源共同支撑，但须记录各自支持的子命题；无关引用移除，原子结论所需证据缺失则不能发布。
- [ ] 无支撑结论删除；部分支持结论缩小范围后再核查。有限次修订后仍失败，返回已核验部分及核验未完成原因。
交付：逐结论可打开证据卡、最终核查正文、稳定引用映射。

## 5. 验收门槛

| 类别 | 必须验证 |
|---|---|
| 真实性 | 真实记录与真实页面通过；伪 DOI、标题错配、预印本冒充正式版不通过；403/429/超时和冲突为待核验 |
| 年份 | 2026 年只接受该年度；2025/2027 拒绝；在线/卷期冲突按已记录口径判断；未知不通过 |
| JIF | IF>10 排除恰为10；IF>=10接受10；旧版本、错期刊、缺来源、缺年度、无法确认最新版本不通过 |
| 语种 | 英文文章通过；非英文拒绝；PubMed 来源但语种未知仍待核验 |
| 关键词 | 正文3/4通过、2/4拒绝；仅参考文献命中不计；重复词、短词误匹配、摘要误标、正文不完整均覆盖 |
| 结论 | 无引用、伪引文、错数字、相关性写成因果、文献不支持、多引用一篇错配均被发现并处理 |
| 完整链路 | rejected/pending 文献不会出现在事实性结论证据中；编号准确；全部出口一致；全剔除不凑数 |
| 降级 | 核验服务断网、关闭模块或修订失败不能发布“严格通过”；仍能返回状态与已核验结果 |

确定性检查：验收样本中违规文献准入数为 0、伪造原文短引通过数为 0、出口一致性通过。
语义检查：人工标注真实样本，分别统计“错误结论被判支持”的比例、正确证据漏检率及结论核查覆盖率；验收集不得保留已知误通过。泛化性能需报告样本规模和实际指标，不声称模型能保证零幻觉。
性能：记录候选数、全文可得率、逐步淘汰原因、调用次数、耗时与 token 成本；M0 建立基线后确定预算并保存于 TaskPolicy。
自动化用例、在线核验和人工完整报告验收分别记录，不以 mock 测试代替实际可用性。

## 6. Git、发布与回滚

每个阶段按可审查任务独立提交，附变更目的、验证证据和未完成依赖。推送与部署分别记录。
先完成代码与本地验证，再在隔离端口/隔离数据环境验收，最后按会话授权范围执行生产切换。
正式切换前保存当前镜像 ID、Compose 生效文件、必要配置及数据备份，避免活跃研究任务期间重启。
新镜像使用独立版本标签；代码回滚与数据恢复分开，正常代码回滚不恢复数据库，不删除数据卷。
基础镜像与部署路径需要可重现；不得用 latest 隐式更换上游版本。
严格核验开关关闭只能进入明确未核验状态，不能作为已验证报告的回滚替代品。
凭据、生产数据、全文缓存和含敏感信息的日志不提交 Git。
本计划不自动变更运行中的服务。
